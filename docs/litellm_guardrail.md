# PII-guardrail для LiteLLM: тестирование «было / стало»

**Было** — встроенный guardrail `presidio` LiteLLM поверх `/analyze` и `/anonymize` pii-service (как в
`docker/litellm_config.yaml` до этого изменения). **Стало** — свой guardrail
[`docker/litellm/pii_guardrail.py`](../docker/litellm/pii_guardrail.py) поверх нового эндпоинта `/mask`.

Детектор (`HybridPIIDetector`) при этом тот же. Все проблемы «было» — в том, как LiteLLM подставляет
метки и возвращает исходные значения, плюс две мелочи в pii-service (код языка `ru` и хэши как TOKEN).

## Как тестировали

- LiteLLM v1.100.1 (основной прогон) и v1.103.0 (текущий `main-stable`, те же 15 кейсов — все ✅).
- «Было» и «стало» подняты рядом — [`docker/e2e`](../docker/e2e/README.md). Вместо модели — заглушка:
  она записывает всё, что LiteLLM отправил «в модель», и отвечает эхом. Так проверяется и что ушло
  наружу, и что вернулось пользователю. Стрим заглушка режет по 7 символов, чтобы метки и ФИО
  попадали на стыки чанков.
- Кейсы с настоящими моделями — Yandex AI Studio: aliceai-llm-flash, yandexgpt-5.1, gpt-oss-120b,
  qwen3.6-35b-a3b, по 3 запуска на модель и версию, стрим.
- Данные синтетические, ИНН и СНИЛС — с верными контрольными суммами.
- Политика в обоих вариантах одинаковая: карта, CVC, TOKEN — BLOCK, остальное — MASK
  («стало»: NAME — PSEUDONYMIZE). Скрипт: [`docker/e2e/run_cases.py`](../docker/e2e/run_cases.py).

## Настоящие модели

Запрос: «Напиши короткое вежливое письмо от имени начальника отдела кадров Сидоровой Анны Викторовны
сотруднику Петрову Ивану Сергеевичу с просьбой предоставить копию СНИЛС … Обратись к нему по
имени-отчеству». В модель в «было» уходит `… кадров <NAME_1> сотруднику <NAME_2> …`, в «стало» —
`… кадров Тарасовой Алины Андреевны сотруднику Беляеву Кириллу Олеговичу …`.

## Что изменено

**pii-service / pii_detector**
- `POST /mask` — маскирует все тексты одного запроса разом: одно значение — одна метка во всём
  запросе, разные значения — разные метки; ФИО — псевдонимы
  ([`pseudonymizer.py`](../pii_detector/pseudonymizer.py)): тот же род и падеж, один человек в любых
  формах («Петров Иван Сергеевич», «Ивану Сергеевичу», «И. С. Петров») — один псевдоним. В ответе —
  пары для обратной замены по всем падежам и вариантам записи (с инициалами, имя-отчество, только
  фамилия), для меток — варианты, в которые их переписывают модели (`[EMAIL_1]`, `EMAIL_1`).
  Найденное значение заменяется во всём запросе, даже там, где NER его пропустил.
- Политика по типам: `PSEUDONYMIZE` / `MASK` / `BLOCK` / `ALLOW`, пороги score, allow-list
  (в запросе или файлом `PII_ALLOW_LIST_FILE`).
- `analyze(language="ru")` — синоним `en` (модель зарегистрирована в Presidio под `en`).
- TOKEN: hex-строка длины хэша с префиксом `sha256:`/`md5:` или рядом со словами digest, commit,
  хэш — не секрет (если рядом нет явного «token:», «api key:»).
- `/analyze` и `/anonymize` не менялись — встроенный guardrail `presidio` работает как раньше.

**LiteLLM — [`docker/litellm/pii_guardrail.py`](../docker/litellm/pii_guardrail.py)**
- До модели: все тексты запроса (история, system prompt, text-части, аргументы tool calls) — одним
  вызовом `/mask`; BLOCK → 400; pii-service недоступен → 503 (connect-таймаут 2 с).
- В ответе: исходные значения в `content`, `reasoning_content`, аргументах tool calls; в стриме
  придерживается только хвост длиной в самую длинную замену. Пробел в заменах совпадает с любым
  пробельным символом (gpt-oss пишет «Сидорова А. В.»).
- Если в запросе есть метки, в system prompt добавляется просьба не изменять их.
- Пары замен хранятся только в памяти процесса LiteLLM, в метаданные запроса попадает непрозрачный
  идентификатор — исходные значения не попадают в журналы и колбэки логирования.
- Другие эндпоинты с текстом (`/v1/responses`, `/v1/messages`, эмбеддинги) по умолчанию отклоняются,
  чтобы ПД не прошли в обход проверки (`pii_unsupported_call_types: allow` — пропускать).

**Стенд:** `docker/litellm_config.yaml` переведён на новый guardrail, образ LiteLLM закреплён на
v1.103.0 (guardrail использует хуки LiteLLM — версию лучше менять осознанно, прогнав e2e).

## Известные ограничения

- Публичные лица тоже заменяются: в «Что писал Менделеев о приисках» вместо фамилии уйдёт псевдоним,
  и модель ответит про другого человека. Отличить публичное лицо от частного детектор не умеет.
- Ложные срабатывания NER остаются: «Ленский расстрел» → `<ADDRESS_1>`, «Ленских приисках» → NAME
  (не разбирается как ФИО — остаётся меткой). Точечно лечится allow-list.
- ФИО не на русском и нестандартные формы (двойные фамилии, только отчество) — обычная метка
  `<NAME_n>`, без склонения.
- Поддержан `/v1/chat/completions` (им пользуется Open WebUI).
- Встроенный guardrail `presidio` в LiteLLM нумерует метки заново в каждом сообщении — это баг
  LiteLLM ([BerriAI/litellm#41600](https://github.com/BerriAI/litellm/issues/41600),
  PR [#31978](https://github.com/BerriAI/litellm/pull/31978)); остальное (стрим, рассуждения,
  падежи) им не исправить в принципе.
